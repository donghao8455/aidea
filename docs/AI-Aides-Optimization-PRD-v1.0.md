# AI-Aides 产品体验优化方案 PRD

> 版本：v1.0 | 日期：2026-06-09 | 作者：AI-Aides Team

---

## 1. 背景与目标

### 1.1 现状

AI-Aides 已完成核心功能搭建：可视化概念图谱（22节点+30关系）、概念详情页（9区块）、分类筛选与搜索、AI新动态侧边栏。技术架构稳定，部署流程完备。

### 1.2 核心问题

| 问题 | 影响 | 严重度 |
|------|------|--------|
| 概念仅22个，覆盖面窄 | 用户搜索高频词搜不到，直接流失 | P0 |
| 首页缺少学习路径引导 | 用户不知从何看起，图谱信息过载 | P0 |
| 页面结构仅两层（首页+详情），过于单薄 | 用完即走，无留存理由，无探索纵深 | P0 |
| 详情页纯文字无可视化 | 阅读疲劳，"关系"认知弱 | P1 |
| 移动端不可用 | 丢失50%+潜在用户 | P1 |
| 搜索能力弱 | 无法搜内容，无自动补全 | P1 |
| AI新动态为Mock数据 | 无实际价值，影响可信度 | P2 |
| 缺少用户参与机制 | 纯消费无留存，无反馈闭环 | P2 |
| URL不规范 | SEO差，分享链接不专业 | P2 |

### 1.3 优化目标

- **短期（1个月）**：概念数量从22扩展至50+，新增学习路径引导，移动端可用
- **中期（2个月）**：详情页迷你图谱、搜索增强、AI新动态接入真实数据源
- **长期（3个月+）**：用户参与机制、SEO优化、数据驱动迭代

## 2. 功能规划

### 2.1 P0 — 内容扩展与学习路径

#### 2.1.1 概念库扩展

**目标**：从22个概念扩展至50+个，覆盖AI领域高频搜索词

**新增概念规划**：

| 类别 | 新增概念 |
|------|---------|
| 基础概念 | Transformer、Attention、Neural Network、Deep Learning、Machine Learning、NLP、Computer Vision、GAN |
| 技术方法 | LoRA、RLHF、DPO、Distillation、Quantization、Pruning、Inference Optimization |
| 方法论 | Few-shot Learning、Zero-shot Learning、Self-Consistency、Tree of Thoughts |
| 架构模式 | MoE、Retrieval Agent、Workflow Agent、AI Native App |
| 工具协议 | Function Calling、A2A、OpenAI API、LangChain |

**数据规范**：每个概念必须包含完整9区块内容，类比理解为必填项

**执行方式**：
- 优先补充搜索量Top 30的AI概念（参考Google Trends / 百度指数）
- 每个概念由AI生成初稿 + 人工审核校准
- 新概念同步补充与现有概念的关系连线

#### 2.1.2 学习路径引导

**目标**：解决"进了首页不知道从哪看起"的问题

**功能描述**：

在首页图谱上方新增"学习路径"入口，提供2-3条预设路径，点击后图谱上高亮路径节点并用虚线连接。

**预设路径**：

| 路径名 | 节点序列 | 适合人群 |
|--------|---------|---------|
| 零基础入门 | Prompt → LLM → Tokenizer → Temperature → Prompt Engineering | AI小白 |
| 应用开发路线 | LLM → RAG → Agent → MCP → Tool Calling | 开发者 |
| 前沿技术路线 | Fine-tuning → RLHF → Reasoning → Test-time Compute → Agentic AI | 研究者 |

**交互设计**：

```
┌─────────────────────────────────────────────────┐
│  🤖 AI概念关系图谱                                │
│  探索AI核心概念及其关系                            │
│                                                   │
│  📌 学习路径： [零基础入门] [应用开发] [前沿技术]    │
│                                                   │
│  [搜索框]                                         │
│  [全部] [基础概念] [技术方法] ...                   │
│                                                   │
│  ┌─────────────────────────────────────────┐     │
│  │           GraphCanvas                    │     │
│  │   路径节点高亮 + 虚线连接 + 序号标注       │     │
│  └─────────────────────────────────────────┘     │
└─────────────────────────────────────────────────┘
```

**路径激活时图谱变化**：
- 路径上的节点保持原色 + 右上角显示序号徽章（①②③...）
- 路径节点间用虚线箭头连接（区别于实线关系）
- 非路径节点降低透明度至0.3
- 路径节点间自动连线，不与已有关系边重叠

**组件设计**：

```
LearningPath
├── PathSelector（路径选择按钮组）
├── PathIndicator（当前路径说明浮层）
└── 传递 pathNodes 给 GraphCanvas
```

**GraphCanvas 新增 Props**：
- `learningPath?: string[]` — 路径概念ID有序数组

### 2.4 P2 — AI新动态真实数据源

#### 2.4.1 数据采集与更新方案

**目标**：将Mock数据替换为真实AI新闻数据，建立可持续的数据管道

##### 方案对比

| 维度 | 方案A：纯采集 | 方案B：AI Agent采集+筛选（推荐） | 方案C：人工审核 |
|------|-------------|-------------------------------|--------------|
| 流程 | GitHub Action → 拉取数据源 → 生成JSON | GitHub Action → 拉取 → LLM筛选/标注/摘要 → 生成JSON | AI采集 → Notion/飞书表格 → 人工审核 → 发布 |
| 自动化 | 全自动 | 全自动 | 半自动 |
| 质量 | 低（无过滤，噪音多） | 高（LLM去重/分类/评分） | 最高（人工把关） |
| 概念关联 | 无 | 有（LLM自动标注relatedConcepts） | 有（人工标注） |
| 运维成本 | 零 | ~$0.5/月（LLM API） | 15-30分钟/天 |
| 扩展性 | 高 | 高 | 低 |
| 风险 | 反爬/数据源失效 | LLM偶尔分类不准 | 依赖人工 |

##### 推荐路径：A→B 渐进式

| 阶段 | 方案 | 时间 | 目标 |
|------|------|------|------|
| Phase 4 | 方案A（纯采集） | 1周 | 先跑通数据管道，验证前端展示 |
| Phase 5起 | 方案B（AI筛选） | 1周 | 加入LLM处理，提升质量和概念关联能力 |
| 长期 | B + 人工抽检 | 持续 | 每周抽检一次分类准确率，持续优化Prompt |

##### 方案A：纯采集架构

```
GitHub Action (每6小时)
  → 拉取各数据源
  → 简单去重（标题相似度）
  → 按时间排序
  → 生成 ai-news.json
  → 提交到仓库 static/data/
  → 前端运行时 fetch 加载
```

##### 方案B：AI Agent采集+筛选架构

```
GitHub Action (每6小时)
  → 拉取原始数据（RSS/API/爬虫）
  → 调用LLM API（GPT-4o-mini）进行：
     · 去重（相似度>80%只保留一条）
     · 分类标注（技术突破/行业应用/学术研究/工具发布）
     · 生成中文摘要（50字以内）
     · 关联概念标注（匹配图谱中的概念ID）
     · 质量评分（1-10，过滤<5分的低质量内容）
  → 生成 ai-news.json
  → 提交到仓库 static/data/
```

**LLM处理成本估算**：

| 项目 | 用量 | 费用 |
|------|------|------|
| GPT-4o-mini | ~50条/天 × 500token | ~$0.015/天 |
| 月成本 | - | ~$0.5/月 |
| 年成本 | - | ~$6/年 |

**核心Prompt设计**：

```

1. 判断是否与AI/人工智能相关，无关则标记skip
2. 分类：tech(技术突破) / industry(行业应用) / research(学术研究) / tool(工具发布)
3. 生成50字以内中文摘要
4. 从以下概念列表中标注关联概念：[llm, rag, agent, mcp, prompt, embedding, vector-db, fine-tuning, chain-of-thought, multi-agent, tool-calling, temperature, tokenizer, prompt-engineering, ai-gateway, reasoning, test-time-compute, agentic-ai, react, rlvr, computer-use, vibe-coding]
5. 质量评分1-10（是否重大新闻、是否有实质内容、是否值得用户关注）

输出JSON格式：
{
  "skip": false,
  "category": "tech",
  "summary": "...",
  "relatedConcepts": ["llm", "reasoning"],
  "qualityScore": 8
}
```

#### 2.4.2 侧边栏体验优化

**现状问题分析**：

| # | 问题 | 影响 | 严重度 |
|---|------|------|--------|
| 1 | 标题单行截断，300px宽度只能显示十几个字 | 用户无法判断内容，信息密度低 | P0 |
| 2 | 每条只显示序号+标题+标签，缺少来源和时间 | 扫一眼获取信息太少 | P0 |
| 3 | Tab切换（热搜/实时/全部）区分度低，8条数据差异不明显 | 切换无感，功能鸡肋 | P1 |
| 4 | 点击新闻无反馈（preventDefault） | 用户困惑，不知道能点 | P1 |
| 5 | 与图谱完全独立，无交互关联 | "知识+资讯闭环"愿景未实现 | P1 |
| 6 | 没有更新时间，不知道数据是否新鲜 | 可信度存疑 | P2 |
| 7 | 8条新闻视觉权重相同，无阅读焦点 | 缺少引导，用户不知道先看哪条 | P2 |

**优化方案**：

##### 优化1：标题2行显示 + 来源时间

**变更**：标题从单行截断改为2行截断，每条下方显示来源和时间

```
现在：
  1  OpenAI 发布 GPT-5：多模态推理能力大... 热

优化后：
  1  OpenAI 发布 GPT-5：多模态推理
     能力实现质的飞跃                  热
     OpenAI Blog · 2小时前
```

**CSS变更**：
- `.newsTitle` 增加 `-webkit-line-clamp: 2`，移除 `white-space: nowrap`
- 新增 `.newsMeta` 行：来源 + 时间，字号11px，颜色#94a3b8

##### 优化2：Tab改为分类筛选

**变更**：将"热搜榜/实时榜/全部动态"改为按内容分类筛选，与图谱分类体系一致

```
现在：[热搜榜] [实时榜] [全部动态]

优化后：[全部] [技术突破] [行业应用] [学术研究] [工具发布]
```

**理由**：
- 与图谱的5大分类（基础概念/技术方法/方法论/架构模式/工具协议）呼应，降低认知成本
- 用户可以只看自己关心的类别，筛选价值更高
- 分类颜色与图谱类别颜色一致，视觉统一

**分类颜色映射**：

| 新闻分类 | 颜色 | 对应图谱类别 |
|---------|------|------------|
| 技术突破 | #00D084 | 技术方法 |
| 行业应用 | #0EA5E9 | 架构模式 |
| 学术研究 | #F59E0B | 方法论 |
| 工具发布 | #EC4899 | 工具协议 |

**短期方案**：点击新闻条目展开摘要（inline展开，不跳转页面）

##### 优化4：与图谱联动（核心差异化功能）

**目标**：点击新闻时，如果新闻涉及图谱中的概念，高亮对应节点，实现"资讯→知识"闭环

**交互流程**：

```
用户点击 "GPT-5 发布" 新闻
  → 新闻条目展开摘要
  → 摘要底部显示 "📍 相关概念：LLM"
  → 图谱中 LLM 节点闪烁高亮（3次脉冲动画）
  → 用户点击 "LLM" 链接
  → 跳转到 LLM 概念详情页
```

**反向联动**：

```
用户在图谱中点击 LLM 节点
  → 侧边栏自动滚动到涉及 LLM 的新闻条目
  → 该条目短暂高亮
```

**数据要求**：每条新闻新增 `relatedConcepts: string[]` 字段，标注关联的概念ID

**组件通信**：
- AINewsSidebar 通过 `onNewsClick(relatedConcepts)` 回调通知首页
- 首页通过 `highlightConcepts: string[]` prop 传递给 GraphCanvas
- GraphCanvas 新增高亮动画逻辑（脉冲3次后恢复）

##### 优化5：第1条新闻显示摘要

**变更**：列表第1条（或标记为featured的条目）默认显示摘要，视觉权重更高

```
1  GPT-5 发布：多模态推理能力质的飞跃        热
```

**样式差异**：
- 第1条：标题14px加粗，摘要12px灰色，行间距更大
- 其余条目：标题12.5px，2行截断

##### 优化6：更新时间显示

**变更**：在侧边栏头部增加最后更新时间

## 6. 风险与应对

| 风险 | 概率 | 影响 | 应对 |
|------|------|------|------|
| 概念内容质量参差不齐 | 高 | 用户信任度下降 | AI生成+人工审核双流程，类比必须人工验证 |
| 图谱节点过多导致视觉混乱 | 中 | 50+节点图谱可读性差 | 引入力导向布局 + 节点折叠 + 缩放级别控制 |
| 移动端图谱性能差 | 中 | 交互卡顿 | 移动端使用Canvas替代SVG / 直接用列表视图 |
| AI新闻采集被反爬 | 低 | 数据源中断 | 多源备份 + 降级为手动更新 |
| X6库升级不兼容 | 低 | 图谱功能异常 | 锁定版本，长期考虑迁移到D3.js |
